PyFormatWhy

What does {x:08.3f} actually do?

Pick an int, float or string and type a Python format spec. PyFormatWhy shows the result, how the spec was read piece by piece (fill, align, sign, #, 0, width, grouping, precision, type), and why: for example why format(2.5, ".0f") is 2, why 2.675 rounds to 2.67 (it shows the exact stored value), or why .3 with no type gives 1.23e+03.

How it was tested

120,000 random (value, spec) cases (6 seeds) against Python 3.10.12's own format(): ints (including huge ones), floats (ties, tiny, huge, inf, nan, -0.0) and strings (accents, CJK, emoji), with random fill, align, sign, #, 0, width, grouping, precision and type. 65,489 gave identical output, 54,511 were errors in both Python and the engine (random specs are often invalid), and 0 differed. The engine rounds floats from the exact binary value with ties to even, as Python does. A first seed was used while building; it found bugs (zero flag on strings, precision with no type, % overflow, character type alignment), all fixed before the counted seeds.

Only the fact that an error happens is checked. The error wording matches Python's in about 83% of the error cases in a sample run, because Python checks options in a different order. Not covered: Decimal, Fraction, datetime, bool, locale-aware n, nested fields, !r. Entirely client-side.
